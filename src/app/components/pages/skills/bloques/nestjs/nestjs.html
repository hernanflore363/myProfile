NestJS – Enterprise Backend Architecture

Guía completa para construir APIs escalables, desacopladas y orientadas a eventos usando NestJS en entornos cloud-native.

Module

Unidad organizacional principal. Agrupa controladores, servicios y providers. 


@Module({
  controllers: [UserController],
  providers: [UserService],
})
export class UserModule {}
Use: modularización

Controller

Expone endpoints HTTP y maneja requests. 


@Controller('users')
export class UserController {

  @Get()
  findAll() {
    return this.service.findAll()
  }
}
Use: capa de entrada

Service

Contiene lógica de negocio y casos de uso. 


@Injectable()
export class UserService {

  findAll() {
    return []
  }
}
Use: business logic

Providers (DI)

Inyección de dependencias automática. 


constructor(private readonly repo: UserRepo) {}
Use: desacoplamiento

Middleware

Intercepta requests antes de llegar al controller. 


@Injectable()
export class LoggerMiddleware implements NestMiddleware {
  use(req, res, next) {
    console.log(req.url)
    next()
  }
}
Use: logging / auth

Guards

Controlan acceso a endpoints (Auth / Roles). 


@Injectable()
export class AuthGuard implements CanActivate {
  canActivate() {
    return true
  }
}
Use: seguridad

Interceptors

Transforman respuestas y manejan logging/metrics. 


@Injectable()
export class LoggingInterceptor implements NestInterceptor {
  intercept(ctx, next) {
    return next.handle()
  }
}
Use: observabilidad

Exception Filters

Manejo centralizado de errores. 


@Catch()
export class GlobalFilter implements ExceptionFilter {
  catch(exception, host) {}
}
Use: error handling

ClientsModule.register([

Clean Architecture Structure 


src/
 ├── domain/
 ├── application/
 ├── infrastructure/
 ├── interfaces/
 │    ├── http/
 │    └── events/

Production Flow

  • Client → API Gateway (Kong)
  • Gateway → Controller
  • Guard → Auth
  • Interceptor → Logging / Metrics
  • Service → Use Case
  • Repository → DB
  • Events → Kafka

Best Practices

  • ✔ Separar domain de infrastructure
  • ✔ No meter lógica en controllers
  • ✔ Usar DTOs + validation pipes
  • ✔ Centralizar errores
  • ✔ Usar interceptors para logs
  • ✔ Integrar Kafka para async
  • ✔ Versionar APIs
  • ✔ Implementar caching (Redis)
