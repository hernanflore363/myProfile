```
Docker Architecture – Production Guide

Guía práctica de Docker para construir, ejecutar, conectar, persistir y distribuir aplicaciones contenerizadas.

Dockerfile

Archivo declarativo que define las instrucciones necesarias para construir una imagen Docker.

``` 

FROM node:22-alpine

WORKDIR /app

COPY package*.json ./

RUN npm ci

COPY . .

EXPOSE 3000

CMD ["npm", "start"]
``` Use: definir cómo se construye una imagen

Image

Plantilla inmutable utilizada para crear contenedores. Contiene código, runtime, dependencias y configuración.

``` 

# Construir imagen

docker build \
  -t my-api:v1 .

# Ver imágenes

docker images

# Ejecutar la imagen

docker run my-api:v1
``` Use: empaquetar aplicaciones

Container

Instancia en ejecución de una imagen. Es un proceso aislado que posee filesystem, red y ciclo de vida propio.

``` 

docker run -d \
  --name my-api \
  -p 3000:3000 \
  my-api:v1

# Ver contenedores

docker ps

# Ver logs

docker logs my-api

# Detener

docker stop my-api
``` Use: ejecutar aplicaciones

Volume

Mecanismo recomendado para persistir información fuera del ciclo de vida del contenedor.

``` 

# Crear volumen

docker volume create mysql_data

# Ejecutar MySQL

docker run -d \
  --name mysql \
  -e MYSQL_ROOT_PASSWORD=secret \
  -p 3306:3306 \
  -v mysql_data:/var/lib/mysql \
  mysql:latest

# Ver volúmenes

docker volume ls
``` Use: persistencia de datos

Network

Permite que diferentes contenedores se comuniquen utilizando una red Docker aislada.

``` 

# Crear red

docker network create backend-network

# MySQL

docker run -d \
  --name mysql \
  --network backend-network \
  -e MYSQL_ROOT_PASSWORD=secret \
  mysql:latest

# API

docker run -d \
  --name api \
  --network backend-network \
  my-api:v1
``` Use: comunicación entre servicios

Docker Compose

Permite definir y ejecutar múltiples contenedores como una única aplicación.

``` 

services:

  api:
    build: .
    ports:
      - "3000:3000"
    environment:
      DB_HOST: mysql
      DB_PORT: 3306

  mysql:
    image: mysql:latest
    environment:
      MYSQL_ROOT_PASSWORD: secret
      MYSQL_DATABASE: appdb
    volumes:
      - mysql_data:/var/lib/mysql

volumes:
  mysql_data:
``` Use: aplicaciones multi-contenedor

Registry

Repositorio donde se almacenan y distribuyen imágenes Docker. Puede ser público o privado.

``` 

# Login

docker login

# Etiquetar imagen

docker tag my-api:v1 \
  usuario/my-api:v1

# Publicar

docker push usuario/my-api:v1

# Descargar

docker pull usuario/my-api:v1
``` Use: distribución de imágenes

Healthcheck

Permite determinar si el proceso dentro del contenedor está funcionando correctamente.

``` 

FROM nginx:alpine

COPY ./health.html /usr/share/nginx/html/

HEALTHCHECK \
  --interval=30s \
  --timeout=5s \
  --retries=3 \
  CMD wget --spider \
  http://localhost/health.html || exit 1
``` Use: verificar estado del contenedor

Multi-stage Build

Permite separar la etapa de compilación de la ejecución, reduciendo considerablemente el tamaño de la imagen final.

``` 

# Build stage

FROM golang:1.24 AS builder

WORKDIR /app

COPY . .

RUN go build -o api .


# Runtime stage

FROM alpine:latest

WORKDIR /app

COPY --from=builder /app/api .

EXPOSE 8080

CMD ["./api"]
``` Use: imágenes pequeñas y seguras

Docker Architecture Flow

  • Dockerfile → Build → Image
  • Image → Container
  • Container → Network → Container
  • Container → Volume → Persistent Data
  • Image → Registry → Deployment
  • Docker Compose → múltiples Containers

Best Practices

  • ✔ Usar imágenes oficiales y versiones específicas
  • ✔ Implementar Multi-stage Builds
  • ✔ No almacenar información persistente dentro del container
  • ✔ Utilizar Volumes para bases de datos
  • ✔ Utilizar Networks para comunicación entre servicios
  • ✔ Implementar Healthchecks
  • ✔ No ejecutar aplicaciones como root
  • ✔ No incluir secrets dentro del Dockerfile
  • ✔ Utilizar .dockerignore
  • ✔ Etiquetar correctamente las imágenes
```
