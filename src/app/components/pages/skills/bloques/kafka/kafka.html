Apache Kafka – Event-Driven Architecture

Guía práctica de Apache Kafka para diseñar arquitecturas distribuidas, desacopladas, resilientes y orientadas a eventos.

Kafka Cluster

Conjunto de brokers que almacenan y distribuyen eventos. Permite escalabilidad horizontal, tolerancia a fallos y alta disponibilidad. 

                    
                    Kafka Cluster

                    ┌──────────────┐
                    │   Broker 1   │
                    ├──────────────┤
                    │   Broker 2   │
                    ├──────────────┤
                    │   Broker 3   │
                    └──────────────┘
Use: alta disponibilidad y escalabilidad

Topic

Canal lógico donde se publican eventos. Los servicios productores escriben eventos y los consumidores los procesan. 

                    
                    payment.completed

                    payment.created
                    payment.completed
                    payment.failed
Use: comunicación basada en eventos

Producer

Aplicación responsable de publicar eventos en uno o varios topics de Kafka. 

                    
                    const event = {
                    eventId: "evt-123",
                    type: "payment.completed",
                    userId: "usr-100",
                    amount: 250,
                    currency: "BOB"
                    };

                    producer.send({
                    topic: "payment.completed",
                    key: "usr-100",
                    value: JSON.stringify(event)
                    });
Use: publicar eventos de negocio

Consumer

Servicio que consume y procesa eventos publicados en Kafka. Puede existir más de un consumidor para el mismo topic. 

                    
                    consumer.subscribe({
                    topic: "payment.completed"
                    });

                    consumer.run( 
                    eachMessage: async ({ message }) => {

                        const event =
                        JSON.parse(message.value);

                        await processPayment(event);
                    }
                    );
Use: procesamiento desacoplado

Consumer Group

Agrupa consumidores para distribuir las particiones de un topic y procesar eventos de forma paralela. 

                    
                    Topic: payment.completed

                    Partition 0 ──► Consumer 1
                    Partition 1 ──► Consumer 2
                    Partition 2 ──► Consumer 3

                    Group: payments-service
Use: procesamiento paralelo y escalabilidad

Partition

División física de un topic que permite distribuir los eventos entre diferentes brokers y consumidores. 

                    
                    Topic: payments

                    Partition 0
                    Partition 1
                    Partition 2
                    Partition 3
Use: paralelismo y escalabilidad horizontal

Offset

Identificador secuencial que permite conocer la posición de un consumidor dentro de una partición. 

                    
                    Partition 0

                    Offset
                    100
                    101
                    102
                    103
                        ▲
                        │
                    Consumer position
Use: control de procesamiento y recuperación

Replication

Kafka replica las particiones entre brokers para evitar pérdida de información ante fallos de infraestructura. 

                    
                    Partition 0

                    Leader
                    Broker 1
                    │
                    ├── Replica → Broker 2
                    │
                    └── Replica → Broker 3
Use: resiliencia y alta disponibilidad

Schema Registry

Gestiona contratos y versiones de los eventos, evitando incompatibilidades entre productores y consumidores. 

                    
                    payment.completed

                    v1

                    userId
                    amount


                    v2

                    userId
                    amount
                    currency
Use: gobierno y evolución de contratos

Retry & Dead Letter Topic

Permite manejar errores de procesamiento sin bloquear indefinidamente el flujo principal de eventos. 

                    
                    payment.completed
                            │
                            ▼
                    Consumer
                            │
                        Error
                            │
                            ▼
                    Retry Topic
                            │
                            ▼
                        DLQ
Use: resiliencia y manejo de errores

Event-Driven Architecture Flow

  • Payment Service → publica payment.completed
  • Kafka → almacena y distribuye el evento
  • Loyalty Service → consume el evento
  • Notification Service → consume el evento
  • Analytics Service → consume el evento
  • Cada servicio procesa el evento de manera independiente
