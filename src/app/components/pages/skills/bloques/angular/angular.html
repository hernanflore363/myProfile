Angular Core

Component

Unidad fundamental de Angular. Encapsula template, lógica, estado y comportamiento visual. 

@Component({
  selector: 'app-user',
  templateUrl: './user.html'
})
export class UserComponent {

  name = 'Hernán';

}
Use: UI modular y reutilizable

Templates

Los templates permiten declarar la interfaz utilizando HTML extendido con bindings y control flow.

Use: renderizado declarativo

Directives

Permiten modificar el comportamiento o apariencia de elementos del DOM. 

@Directive({
  selector: '[appHighlight]'
})
export class HighlightDirective {

  constructor(
    private el: ElementRef
  ) {}

}
Use: comportamiento reutilizable

Pipes

Transforman datos directamente desde el template.

Use: transformación de datos

Dependency Injection

Angular proporciona un sistema de inyección de dependencias para administrar servicios y recursos. 

@Injectable({
  providedIn: 'root'
})
export class UserService {

  constructor(
    private http: HttpClient
  ) {}

}
Use: desacoplamiento y testabilidad

Services

Encapsulan lógica de negocio, acceso a APIs, estado compartido y funcionalidades reutilizables. 

@Injectable({
  providedIn: 'root'
})
export class PaymentService {

  getPayments() {
    return this.http.get('/api/payments');
  }

}
Use: lógica de negocio

Signals & Reactive State

signal()

Permite representar estado reactivo de forma granular. 

count = signal(0);

increment() {
  this.count.update(
    value => value + 1
  );
}

computed()

Define valores derivados de otros signals. 

price = signal(100);
quantity = signal(2);

total = computed(
  () => this.price() * this.quantity()
);

effect()

Ejecuta efectos secundarios cuando cambian signals. 

effect(() => {

  console.log(
    this.count()
  );

});

Signal Inputs

Comunicación reactiva entre componentes. 

user = input<User>();

name = computed(
  () => this.user().name
);

RxJS & Reactive Programming

Observable

Representa una secuencia de valores que puede emitirse de forma síncrona o asíncrona. 

users$ = this.http.get<User[]>(
  '/api/users'
);

Operators

Permiten transformar, combinar y controlar streams. 

this.http.get('/api/users')
  .pipe(
    map(users => users),
    filter(users => users.length > 0),
    catchError(error => ...)
  );

switchMap

Cancela la operación anterior cuando llega una nueva emisión. 

search$
  .pipe(
    debounceTime(300),
    switchMap(term =>
      this.search(term)
    )
  );

Subjects

Permiten actuar como Observable y Observer. 

private refreshSubject =
  new Subject<void>();

refresh() {
  this.refreshSubject.next();
}

Routing & Navigation

Angular Router permite construir aplicaciones SPA con navegación, parámetros, guards, lazy loading y resolvers. 

export const routes: Routes = [

  {
    path: '',
    component: HomeComponent
  },

  {
    path: 'dashboard',
    loadComponent: () =>
      import('./dashboard.component')
  },

  {
    path: 'admin',
    canActivate: [authGuard],
    loadChildren: () =>
      import('./admin.routes')
  }

];

Lazy Loading

Lazy Components

Carga componentes únicamente cuando son requeridos. 

{
  path: 'reports',

  loadComponent: () =>
    import('./reports.component')
}

Lazy Routes

Divide la aplicación en diferentes áreas funcionales. 

{
  path: 'admin',

  loadChildren: () =>
    import('./admin.routes')
}

HTTP & API Integration

HttpClient

Cliente HTTP utilizado para consumir APIs REST, servicios backend y microservicios. 

getUsers() {

  return this.http.get<User[]>(
    '/api/users'
  );

}

HTTP Interceptors

Permiten interceptar solicitudes y respuestas HTTP. 

export const authInterceptor:
HttpInterceptorFn = (req, next) => {

  const token = authService.token();

  const request = req.clone({

    setHeaders: {
      Authorization:
        `Bearer ${token}`
    }

  });

  return next(request);

};

Error Handling

Permite controlar errores de comunicación y presentar respuestas consistentes al usuario. 

this.http.get('/api/users')
  .pipe(
    retry(2),
    catchError(error => {

      console.error(error);

      return throwError(
        () => error
      );

    })
  );

OnPush

Reduce verificaciones innecesarias utilizando una estrategia de detección de cambios más eficiente. 

@Component({

  changeDetection:
    ChangeDetectionStrategy.OnPush

})

Permite identificar elementos de una colección para minimizar operaciones innecesarias en el DOM.

Lazy Loading

Cargar funcionalidad únicamente cuando el usuario la necesita reduce el JavaScript inicial.

Deferrable Views

Permiten retrasar la carga de partes de una interfaz.

Angular Production Flow

  • User → Angular Application
  • Router → Feature
  • Component → Service
  • Service → HttpClient
  • HttpClient → API Gateway
  • API Gateway → Microservices
  • Microservices → Database / Events
  • Response → Service → Signal / Observable
  • State → Component
  • Component → UI

Angular Enterprise Best Practices

  • ✔ Utilizar componentes pequeños y cohesivos
  • ✔ Separar features por dominio
  • ✔ Evitar lógica de negocio compleja en templates
  • ✔ Utilizar Signals para estado local cuando corresponda
  • ✔ Utilizar RxJS para streams y operaciones asíncronas
  • ✔ Utilizar OnPush cuando corresponda
  • ✔ Implementar Lazy Loading
  • ✔ Centralizar autenticación mediante interceptors
  • ✔ Implementar Route Guards
  • ✔ Manejar errores HTTP de forma centralizada
  • ✔ Evitar suscripciones manuales innecesarias
  • ✔ Mantener componentes desacoplados
  • ✔ Utilizar interfaces y tipos fuertes
  • ✔ Separar Core, Shared y Features
  • ✔ Implementar testing automatizado
  • ✔ Aplicar principios SOLID
  • ✔ Evitar lógica duplicada
  • ✔ Medir performance antes de optimizar

Architect Perspective

Angular no debe considerarse únicamente como un framework para construir interfaces. En aplicaciones empresariales, debe formar parte de una arquitectura tecnológica completa, integrándose con API Gateways, microservicios, sistemas de identidad, observabilidad, CI/CD y plataformas cloud-native.

Una arquitectura Angular correctamente diseñada debe priorizar separación de responsabilidades, modularidad, escalabilidad, seguridad, mantenibilidad, observabilidad y experiencia de usuario.
